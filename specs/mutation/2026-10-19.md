## Prune (Task 4)

**Inputs.**
- **The candidates:** the 18 DELETE candidates in laika's prune report (laika `3ca8368:specs/test-prune/2026-10-18.md`, the VCT and KABT tables), handled in the report's order.
- **Line numbers:** each `VCT:`/`KABT:` line number is resolved to its test method at `9a390dc`, where the moved files still match laika's lines. Removals are made by method name, because each removal shifts the lines below it.

**Procedure for each candidate.**
1. Quote Task 3's mutants on the candidate's cited production lines.
2. If one of them is anything other than "not covered", remove the test and keep every earlier proven removal.
3. Delete `mutation.json` and run `composer mutation`.
4. `diff` the `bin/mutants.php` list against `accepted.txt`.

Step 3 deletes `mutation.json` first so that a run which writes nothing cannot be compared as a stale log. A provider goes with its last test.
